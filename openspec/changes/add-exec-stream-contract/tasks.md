## 1. The primitive (no consumer changes yet)

- [x] 1.1 Add `core/exec_stream.py` with `exec_stream(container, cmd, *, workdir=None, environment=None) -> Iterator[ExecEvent]` (**shipped taking a LIVE container, not the `container_id` originally specified - see 4.6**), yielding `ExecChunk(stream, text)` per chunk then exactly one terminal `ExecDone(exit_code)`. It is a PER-EXEC primitive, NOT per-verb: `run` is the only consumer with one exec per resolve, while `update` has 13 and `init` has 11 downstream of a single resolve (design Decision 1).
- [x] 1.2 Define the `ExecChunk` / `ExecDone` DTOs (frozen, slots, kw_only; every field a builtin). **`ExecDone.exit_code` is `int`, NOT `int | None`** - the fail-open this batch exists to fix must be unrepresentable in the type. `ExecDone` is a terminal EVENT, not a generator return value: a `return` value is reachable only via `StopIteration.value`, which no consumer would remember to read.
- [x] 1.3 Poll the exit code as `update.py:47-56` already does, but **BOUNDED** so it cannot hang: poll `exec_inspect` while the code is unknown and the exec reports running. `exec_inspect` returns `{"ExitCode": None, "Running": True}` while an exec is still going, so the key is PRESENT and `.get("ExitCode", 1)`'s default is dead code. Never coerce `None` to `0`.
- [x] 1.4 When the code is genuinely unknowable (settled with `Running: False` and no code, or the bound expired with `Running: True` - the dropped-connection case, since `CancellableStream.__next__` swallows `ProtocolError`/`OSError` into `StopIteration`), raise `CwcliError(DOCKER)` naming the lost stream. Do NOT report `0` (a success that did not happen) and do NOT report `1` (a command failure that may not have happened). **Pick the bound in implementation and pin it with a test on the BOUNDARY, not on the number** (design Decision 7, Open Questions). **Bound: 10s at 0.1s intervals.** Pinned by BOUNDARY tests (`test_lost_stream_while_still_running_raises_rather_than_guessing` expires; `test_poll_settles_within_the_bound_rather_than_expiring` settles), never by the number - both shrink the constant.
- [x] 1.5 Always `demux=True`; tag every chunk `"stdout"`/`"stderr"`. **No `demux` parameter.** Verified equivalent to today's `demux=False`: docker-py builds the same `frames_iter(socket, tty)` in both modes and differs only in the per-frame wrapper (`docker/api/client.py:_read_from_socket` + `demux_adaptor`), so a consumer writing both tags to stdout in yield order reproduces today's byte stream exactly. The tag is REQUIRED because `init.py:171` routes stderr to `sys.stderr` and a tagless event loses that when `init` migrates (design Decision 4).
- [x] 1.6 Decode via `utils.docker_utils.utf8_stream_decoder`, **one decoder PER stream** (two per exec), exactly as `init.py:173-174` does. Sharing one would feed stderr's bytes into stdout's pending character and mangle both. Do NOT reinvent the decoder - PR #79 already shipped it.
- [x] 1.7 Close the `CancellableStream` in a `finally`, so an early `break` or a mid-render exception releases the socket. This is the caller's DOCUMENTED responsibility (`docker/api/client.py:_read_from_socket`: "the caller is responsible for closing the response") and not one of the four current consumers does it. Close defensively (the fakes in tests have no `close`).
- [x] 1.8 ~~Resolve the container from `container_id` inside the primitive.~~ **SUPERSEDED (see 4.6).** The primitive takes a live container and uses `container.client.api`, so it resolves nothing and constructs no client. The id-to-handle bridge moved to `core/docker.py:get_container`, called by `core.run_stream` - the only caller that has an id rather than a handle. No cached client anywhere, as originally intended.
- [x] 1.9 Unit-test the primitive against a faked exec API: tagged chunks in order; the terminal `ExecDone`; a mid-character split round-tripping exactly; stdout/stderr decoding independently; `ExitCode: None` then a real code -> that real code (NEVER 0); an unknowable code -> `CwcliError(DOCKER)`; a non-zero code passed through; an empty stream; the stream closed on early `break` and on an exception.
