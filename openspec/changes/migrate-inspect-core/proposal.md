## Why

`inspect` is the cache's producer: every bench verb resolves through data only `inspect` writes, and five subsystems invoke it purely to populate that cache.
It is the largest un-migrated read command (672 lines), and its un-migrated state is the pivot three standing problems hang on, all measured by the recon in `cwcli-inspect-recon-i7` (report re-verified against this HEAD; the delta since its `4146c95` baseline is doc-only).

**1. `core/update.py`'s reach-back into the CLI layer exists because `core.inspect` does not.**
`cache.recache_project` (`utils/cache.py:38-50`) clears the cache and then calls the `inspect` Typer COMMAND; `core/update.py:389` calls it mid-fan-out, making `core/update.py` the ONE core module that imports the CLI layer at runtime - a violation the ledger explicitly marks "fixed properly by inspect's own migration".
This batch fixes it at the root: `recache_project` keeps its signature and its never-prompt / False-when-stopped contract, but its body re-points at `core.inspect`, so all three of its callers (`rm.py`, `apps.py`, `core/update.py`) are untouched and the reach-back dies.

**2. Every logic caller of `inspect` pays the Typer-default trap.**
`inspect` is a Typer command, so an omitted parameter is a truthy `typer.Option(...)` default OBJECT; the seven call sites that invoke it as a function must each pass all nine params explicitly, and one (`open.py:135-147`) already omits `prompt_to_start` and silently gets the truthy object.
A keyword-only core function with real defaults eliminates the trap class, not just the instances.

**3. `axi benches` dead-ends agents at a human command.**
On an uninspected project it errors NOT_FOUND telling the agent to run `cwcli inspect` (`axi.py:508-510`) - the exact class of agent dead end `axi benches` itself was built to close one level up.
There is no `axi inspect`; this batch ships one and re-points the hint.

Beyond the three, the migration is the sequencing key: `open` is deferred ON `inspect` (its only two logic edges are `open.py:135` and `:217`, both served by this batch's surface - recon Q8 confirmed nothing else blocks it).

## What Changes

- **`core/inspect.py`**, the tiered read on the core: `core.inspect(project_name, *, refresh="auto"|"cache_only"|"full", auto_start=False, offer_choice=True, on_event=None) -> Result[InspectReport]` owns the T1/T2/T3 tier state machine, the discovery + gather fan-out, AND the cache write (design Decision 2: the write is the product for five of seven consumers; T2's never-write / T3's write-on-success / drift-degrade's serve-without-persist are one contract that must not be re-implementable per frontend).
- **`InspectReport` is a frozen, serializable DTO** mirroring the human `--json` shape (project, benches with index/path/label/current_site/available_apps/sites), plus `served_from: "cache"|"partial"|"full"` and `degraded: bool` for the drift-fallback path. No live Docker object crosses the return boundary.
- **A plain function, NOT a generator, NOT two-phase** (design Decision 1): nothing consumes intermediate results, `NEEDS_CHOICE`/`confirm_start` must be returnable at call time (a generator cannot), and nothing streams - every probe is a short buffered `exec_run`, so `exec_stream` is deliberately not consumed, same reasoning class as `core/logs.py`'s measured refusal. The `--verbose` trace rides the typed-event `on_event` callback (batch 5's amended decision: `warnings` is for actionable notes, never debug echoes).
- **`partial_refresh(container, cached_benches)`** - the moved T2 pass, keeping cache-shaped dicts as its return (they ARE the cache shape; DTO-ifying an internal pass forces a convert-back at the cache boundary for zero consumer benefit), with its pinned carry-forward / drop-vanished / never-write behaviors unchanged.
- **`discover_benches(container)`** - the moved discovery, killing `rm.py:804`'s import of the underscore-private `_find_bench_instances` across a module boundary. The `sorted(set(...))` order IS the numeric-label order and moves byte-identical.
- **`commands/inspect.py` thinned to a renderer** (backup pattern: interactive prologue outside the spinner, capped `confirm_start` retry, `TipSpinner` around the core call, tree/`--json` renderers). The `-i` labeling loop stays in the frontend operating on returned data with today's write ordering - unifying it onto `core.label.set_label` would change write ordering and per-bench cache round-trips, a behavior change wearing a migration's clothes.
- **All seven logic-consumer edges re-pointed** (recon Q4 #1-#7): `utils/cache.py`'s body, `auto_inspect._inspect_project`, `open.py:135` (fallback populate) and `:217` (in-memory `--app` freshness, now `partial_refresh`), `update.py:475`'s fallback, `restore.py`'s three fallback copies, `rm.py:804`'s live discovery. The frontend-calling-frontend class dies entirely.
- **One `axi inspect` verb**: `cwcli axi inspect <project> [--update] [--no-refresh]` - the tier machinery IS the read-with-freshness contract, so no read/refresh verb split that would make agents orchestrate tiers by hand. Deliberately NO `--yes` (an axi verb must never open a start-from-axi path; a stopped project on the refresh path is `emit_axi_choice_as_usage_error`, exit 2, naming `cwcli start`). The `axi benches` not-inspected hint re-points at it; the generated skill picks the verb up via `build_skill.py`.
- **Two hardenings, disclosed not smuggled**: the strict `.decode("utf-8")` at `inspect.py:34` (a non-UTF-8 byte in any probe crashes the whole inspect today) becomes `errors="replace"` per the core idiom; a raw docker exception escaping the T3 fan-out (caught by NOTHING today - `@handle_docker_errors` only wraps the ping) becomes `CwcliError(DOCKER)`. Both are error-rendering improvements, not outcome changes.
- **`--show-apps` stays byte-identical.** It is a dead flag (declared, never read; the tree always shows apps), and its disposition is a separately-held captain decision (`cwcli-inspect-recon-i7-decision-show-apps-dead-flag`), not this batch's.

## Impact

- **New:** `src/caffeinated_whale_cli/core/inspect.py`, `tests/test_core_inspect.py`, `tests/test_axi_inspect.py`, the `axi inspect` verb in `commands/axi.py`.
- **Changed:** `commands/inspect.py` (renderer), `utils/cache.py` (body only), `utils/auto_inspect.py`, `commands/open.py`, `commands/update.py`, `commands/restore.py`, `commands/rm.py` (each: the inspect edge only), `skills/cwcli/SKILL.md` (regenerated), existing inspect test suites (patch targets move with their subject; assertions unchanged unless named by design), CLAUDE.md ledger + `cwcli-inspect-benches` / `cwcli-core-axi` skills (including the stale `start`-as-caller line, which greps to zero).
- **Unchanged:** the cache schema and dict shape (including the RAW `installed_apps` line format `core/update._sites_with_app` depends on - tasks-§8's tracked decision, not this batch's), `db_utils.cache_project_data` (still the single redaction chokepoint; its non-transactionality is a reported follow-up), the human `--json` output (byte-identical), the tree renderer, every exit code, `core/exec_stream.py`.
- **Zero new primitives, as a falsifiable claim** (recon's predicted verdict): `resolve_container_state` already covers both the prompting (T3, `offer_choice=True`) and spinner-borne (`offer_choice=False` + caught `NOT_RUNNING`) callers; `resolve_bench` is not needed (whole-project verb); the moved helpers take containers as parameters, which is allowed. The one novelty - the first core verb whose primary side effect is the cache write - is covered by the `core/label.py` precedent, not a primitive change. If implementation finds otherwise, it is reported, per the standing rule.
