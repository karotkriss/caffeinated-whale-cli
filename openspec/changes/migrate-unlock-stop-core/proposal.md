## Why

The core rework's foundation (`core-logic-foundation`) migrated `backup` as the reference slice, and `migrate-start-status-core` followed with `start`/`status`/`restart`.
Six commands now sit genuinely on the core with matching `cwcli axi` verbs: `backup`, `ls`, `where`, `start`, `status`, `restart` (verified per command against the real code, see the audit below).
The open question that batch left is whether the core primitives it extracted were built for `backup` specifically or are genuinely general.

`unlock` is the cheapest possible answer, because it is `backup`'s near-twin.
`commands/unlock.py:54-158` maps step for step onto `core/backup.py:55-136`: ensure-running (`unlock.py:55` / `backup.py:58`), resolve the frappe container (`unlock.py:57-70` / `backup.py:55`), resolve the bench with the same default-path fallback (`unlock.py:74-83` / `backup.py:63-76`), resolve the default site (`unlock.py:86-111` / `backup.py:81-98`), validate the site name against a shell-metacharacter list that is character-for-character the same list (`unlock.py:119` / `backup.py:24`), validate the bench path (`unlock.py:128-133` / `backup.py:111-116`), `test -d` the bench (`unlock.py:138-147` / `backup.py:120-126`), `test -d` the site (`unlock.py:151-158` / `backup.py:130-136`).
It diverges only at the operation itself: `rm -rfv <site>/locks` instead of `bench --site <site> backup`.
So migrating `unlock` adds ZERO new core primitives.
If it does not fall straight out of `core/resolvers.py` + `core/docker.py` + the envelope, the foundation was overfitted to one command, and we want to learn that on a 194-line command rather than on `restore` (2118 lines).

`stop` is included for three reasons the code makes concrete, not for symmetry.
First, it is genuinely thin (118 lines) and `_stop_project` (`commands/stop.py:13-49`) already returns a count-or-`None` proto-DTO, the same "gropes toward the envelope" shape the recon found in `list`.
Second, it is the missing sibling of an otherwise complete family: `start`, `status`, and `restart` are all on the core with axi verbs, so an agent can `cwcli axi start` a project but has no way to stop one.
Third, and most concretely, `_stop_project` is a `rich`-printing function that four modules depend on (`restart.py:15`, `start.py:135`, `rm.py:1222`, and `axi.py:332`), including cwcli's most destructive path (`rm`'s backup gate) and the agent surface itself.
It prints rich markup to **stdout** at `stop.py:23` ("Error: Project '<name>' not found.") and `stop.py:39` ("Instance '<name>' is already stopped."), and `commands/axi.py:332-335` calls it from `axi start --yes`'s port-conflict resolution.
The comment there claims the call is "running -> stdout-silent", which holds only on the happy path: it is an assumption about which internal branch `_stop_project` takes.
A teardown race, exactly the race the adjacent code at `axi.py:340-348` already guards against, reaches those two stdout prints and corrupts `axi`'s single-TOON-document contract.
Migrating `stop` closes that hole structurally rather than by comment, and hands all four callers a callee that cannot print.

## What Changes

- **`core.unlock` on the existing primitives, no new ones.** Add `core.unlock(project, *, site=None, bench=None, bench_path=None) -> Result[UnlockOutcome]` reusing `core_docker.get_frappe_container`, `resolvers.resolve_container_state`, `resolvers.resolve_bench`, and `db_utils.get_default_site` exactly as `core/backup.py` does, then removing `{bench_path}/sites/{site}/locks`. The shared metachar validation and the `test -d` probes are lifted from `core/backup.py` into one shared helper rather than copied a second time (the duplication is the point of the exercise: two callers is when it earns extraction).
- **`unlock`'s verbose stream becomes a buffered, structured result (NO streaming machinery).** The recon called `unlock`'s verbose path "the typed event iterator case" and the rework defers streaming to `logs`/`update`. The code disagrees with that diagnosis: the stream (`unlock.py:166-183`) carries `rm -rfv` output for a locks directory, a handful of small lock files completing in milliseconds. It streams so verbose mode can echo removed paths, not because the output is large or long-lived. So `core.unlock` runs the `rm -rfv` buffered (one `exec_run`, exactly as `core/backup.py:156` does) and returns the removed paths as `UnlockOutcome.removed: list[str]`. The CLI prints them under `--verbose`; `axi` gets a structured list, which is strictly better than an opaque byte stream. This change therefore pulls in NO deferred machinery, and retires the "unlock is the streaming case" note so a later agent does not build an event iterator for a millisecond-scale `rm`.
- **`core.stop` and the four callers.** Add `core.stop(project) -> Result[StopOutcome]` owning container lookup and the stop loop, returning `StopOutcome(project, stopped, already_stopped, containers)`; a project that does not exist raises `CwcliError(NOT_FOUND)` rather than returning `None`, which is what `_stop_project`'s sentinel was standing in for. Reseat `commands/stop.py` as a thin frontend (the variadic argument list, stdin piping, the trailing-`-v` recovery, the spinner, and `rich` output all stay in the frontend), and re-point `restart.py`, `start.py`, `rm.py`, and `axi.py` at the core function.
- **Two new axi verbs.** `cwcli axi unlock <project> [--site] [--bench] [--yes]` and `cwcli axi stop <project>`, on the existing serializer and exit-code mapper in `commands/axi.py`. Neither prompts: a stopped container without `--yes` and a multi-bench project without `--bench` become structured usage errors naming the flag, per the established `axi backup` pattern.
- **An `unlock` E2E in both modes (a standing-policy gap, not new scope).** `unlock` is a prompting command (the auto-start confirm via `ensure_containers_running`, `unlock.py:55`) with a `--yes` flag, and the captain standard requires every prompting command to be E2E-verified in BOTH interactive and non-interactive modes. It has no E2E today (`tests/e2e/` holds backup, init, start/status, supervisor, and harness suites only). Migrating it without one means refactoring blind, so this change adds that E2E as the migration's safety floor. `stop` needs no new E2E: it is already driven and asserted by the green net (`test_start_status_e2e.py:103,140`, `test_status_unsupervised_e2e.py:52`).
- **NOT BREAKING.** Both commands keep their CLI surface, flags, messages, and exit codes. The one disclosed behavior nuance is `unlock --verbose`: removed paths print at completion rather than incrementally. For a sub-second `rm` of a locks directory the two are indistinguishable, and the same information is emitted to the same stream.

## Capabilities

### New Capabilities

- `unlock-core-slice`: `core.unlock(...) -> Result[UnlockOutcome]` built entirely from the foundation's existing primitives (the generality proof), with the `rm -rfv` buffered into a structured `removed` list instead of streamed; the shared bench-op validation helper extracted from `core/backup.py` on its second caller; the reseated thin `cwcli unlock`; the `cwcli axi unlock` verb; and the both-modes `unlock` E2E that gives the migration its safety floor.

## Non-Goals

- **`open` is deliberately EXCLUDED, on evidence.** The dispatch offered `open` if it proved as thin as `unlock`. It does not, for a reason that is structural rather than a matter of size. `open` ends in `exec_into_container` (`open.py:359`), which uses `os.execvp()` to REPLACE the process and never returns (`docker_utils.py:135-157` documents this explicitly). A core function's contract is `-> Result[DTO]`; a function that never returns cannot return an envelope, and the terminal handover is the command's entire purpose, not an incidental side effect. There is also no coherent axi verb: `cwcli axi open` would hand an agent an interactive bash shell or launch a VS Code window on the host desktop, and neither is serializable TOON. It further depends on the un-migrated `inspect` monster (`open.py:135,217` import `inspect` and `partial_inspect_known_benches`), so migrating it cleanly would drag 672 deferred lines along. `open` needs its own decision about how a process-handover command relates to the core at all, which is a design question, not a batch item.
- **Streaming event-iterator machinery.** Deferred to `logs`/`update` by the rework, and this change does not need it: `unlock`'s only streaming path is replaced by a buffered structured result (see What Changes).
- **A plan/apply split.** `unlock` removes a locks directory and `stop` stops containers; both are recoverable and neither needs a preview boundary. Plan/apply arrives with `restore`/`rm`.
- **The monsters.** `init`, `apps`, `config`, plus `inspect`, `restore`, `rm`, `label`, `logs`, `run`, `self_update` stay un-migrated. They are later changes, once this pattern is boring.
- **The AXI cross-cutting shell.** The SessionStart hook, the installable skill, `skills-lock.json`, and the content-first home refinements remain the narrowed `cwcli-axi-pass-x9`. This change adds two verbs on the existing surface.
- **Refactoring `rm`'s or `start`'s own logic.** Their callers are re-pointed at `core.stop` and nothing more; their behavior is unchanged.
